Host boundary
createRecoveryHost accepts explicit server-side inputs only. A future reviewed
enrollment must bind fixed existing recovery project xkx, exact intended owner,
review reference, recovery-specific branch, revision, exact private Preview
origin and a window of at most fifteen minutes. The declared deployment must
match and require Vercel authentication. Original source branches/origins,
production, foreign target, mismatched revision and incomplete fields deny.
The fifteen-minute maximum is a proposed restrictive limit, not an approved
window. No actual owner, origin, revision, window or key is configured.

These descriptor checks are not authenticated proof of the platform, protection,
identity, account, approval or custody. Future actual Preview URL assignment may
not match the intentionally narrow recovery-name pattern: HOLD for review, never
automatically normalize/relax it. The private branch/protection/build/target

Only exact raw GET /api/recovery-readonly reaches the adapter. Query/hash,
absolute URL, normalization aliases, foreign host/origin and bodies reject before
Auth. Only required authorization/host/origin/site headers are forwarded; Cookie
and x-forwarded values are not authority and are not forwarded. Throwing body
accessors reject400. No Command/task/checkout/refund/sender/scheduler route is
imported. Raw-body/cancellation config is proposed, not tested on Vercel.

A separate adapter per request preserves cancellation isolation. AbortSignal,
request aborted/error and unfinished response close abort that operation. A
normal request close alone is not cancellation. The host buffers the adapter
result, checks its original five-second handler budget, finite enrollment and
last observed wall/monotonic values through headers/body consumption and final
commit, then emits only sanitized stored records. The frozen adapter keeps its
fresh GetUser and pre/post current-owner/session checks, no new SQL or grant.

One explicit browser exercise
The coordinator derives provider and view enrollments from the same validated
owner/project/email/origin/branch/revision/window descriptor. It never reads those
values from query, cookies, DOM attributes or arbitrary request data. The public
key remains a future explicit browser input, not an embedded working value; the
server secret never enters browser code. Default input is disabled and absent
configuration cannot consume a password or make a request.

After a separately approved configuration, one explicit Open click is allowed:
1. The provider clears the input and sends the privately entered existing
   password directly to fixed xkx Auth. No password passes through this server,
   source Command, storage or assistant artifact. It verifies fresh GetUser,
   target issuer/owner/session and returns one access token in closure memory.
2. The frozen view sends one same-origin GET to the host. Its five backend reads
   are two GetUser/current-session pairs around one stored overview. Tokens never
   become URL/HTML/log/storage values; decoded claims only deny, never authorize.
3. The view aborts its completed operation signal. The provider therefore begins
   one local-scope logout immediately after that read. The coordinator awaits its
   actual confirmed/unconfirmed status while retaining only the stored snapshot.
   It does not retain the session until Finish or reuse the token.
4. Finish clears records immediately and reports the existing cleanup result.
   It cannot send another logout or login. A later exercise needs a new separately
   reviewed instance/window; focus/return never restarts it automatically.

A replaced coordinator/provider cannot clear a newer installation’s password.
The provider tracks input ownership; the coordinator gates old async finalizers
on its installation generation. Immediate destruction still clears the old
input before handing control to a replacement.

Blur, hidden visibility and pagehide clear private display and request best-effort
cleanup. Late results cannot restore rows or alter the finished UI. A lost login
reply is unconfirmed, never proof no session was created; no retry is attempted.
A late target token can receive one bounded cleanup attempt without handout.
No cleanup response or window expiry by itself proves global revocation. A failed
or unavailable receipt stays unconfirmed. No refresh token is used or persisted.

The HTML CSP permits same-origin assets/API plus only the fixed xkx Auth origin.
There is no form navigation or external asset. This necessary browser allowance
is not provider authentication proof. The coordinator's old hidden controls do
not expose a second Open/clear route. Its visible status distinguishes held,
stored-record and cleanup outcomes; provider health/live readiness stays unknown.

Deployment and lifecycle limits
package/vercel.json proposes a vanilla Node API/static-page layout with
cancellation. It has not been deployed or platform-built. This package root
cannot simply replace the existing project root/site. Future separate-branch
root/build integration, immutable deployment tuple, protection, routes, headers,
compression and actual browser/host cancellation must be concretely reviewed
and accepted. Code requires no new project; none is authorized by this artifact.
No publication or activation approval is inferred from source completion.

Local timers cannot preempt synchronous CPU, prove remote SQL completion by a
deadline, undo an already-sent request, globally stop old deployments, or revoke
a server key. Close affects only the local factory. Immutable old deployments,
server-key custody/revocation and local-session cleanup require actual operational
acceptance. Pre/post session checks do not linearize revocation with the remote
read or final network delivery. JavaScript clearing is not secure memory erasure.
The provider's successful local logout does not prove every session is revoked.
